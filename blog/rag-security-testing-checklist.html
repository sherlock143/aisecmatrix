RAG Security Testing Checklist

Retrieval-augmented generation (RAG) connects an LLM to your own documents. That makes answers useful — and makes the document store, the retrieval layer and the ingestion pipeline part of your attack surface. Use this checklist to scope and run a RAG security assessment. Items map to the OWASP Top 10 for LLM Applications.

1. Access control and tenant isolation (LLM08, LLM02)

  • Is retrieval filtered by the requesting user's permissions, or does the bot see everything it was indexed with?
  • In multi-tenant systems, is tenant ID enforced in the vector query itself — not just in the prompt?
  • Ask for documents you shouldn't see by title, topic, author or quoted phrase.
  • Check whether deleted or permission-revoked documents are still retrievable (stale index).
  • Confirm the vector database is not internet-exposed and requires authentication.

2. Ingestion and poisoning (LLM04, LLM01)

  • Who can add or edit content that gets indexed — employees, customers, the public web?
  • Plant a document containing an indirect prompt injection and check whether it is retrieved and obeyed.
  • Test hidden payloads: HTML comments, white text, PDF metadata, alt text, Unicode tag characters. Pre-screen samples with the Prompt Injection Checker.
  • Does ingestion strip hidden text and invisible characters before embedding?
  • Can a planted document crowd out legitimate answers for high-value queries (e.g. "how do I reset my password")?

3. Output and exfiltration (LLM05, LLM02)

  • Are citations and links in answers restricted to trusted domains?
  • Are external markdown images rendered automatically? If yes, test image-URL data exfiltration.
  • Is model output HTML-encoded before display?

4. Sensitive data in the corpus (LLM02)

  • Scan the corpus for secrets, credentials and PII that should never have been indexed.
  • Try to extract them with targeted questions ("list any API keys mentioned in the engineering docs").
  • Assess embedding-inversion risk for highly sensitive text stored as vectors.

5. Abuse and availability (LLM10)

  • Rate limits on queries and on document upload / ingestion.
  • Maximum document size and number of retrieved chunks.
  • Behaviour with very large or malformed files.

FAQ

What are the main security risks in RAG applications?

Missing per-user authorisation on retrieval, cross-tenant data leakage, indirect prompt injection and poisoning through indexed documents, sensitive data in the corpus, and data exfiltration through rendered links and images.

How do you secure a vector database?

Keep it off the public internet, require authentication, enforce tenant and user permissions inside the query filter, remove revoked content promptly, and avoid indexing secrets or unnecessary personal data.
